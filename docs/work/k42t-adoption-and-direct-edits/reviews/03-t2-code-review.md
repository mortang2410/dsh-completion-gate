## Spec

The revised design is described in the skeleton at [skeleton.md:37-105](/home/wilder/dsh-test/dsh-completion-gate/docs/work/k42t-adoption-and-direct-edits/skeleton.md#L37-L105). Its contracts name four parts of T2: C1 reads file-tool events, C2 converts their paths to canonical absolute paths, C3 tracks only the overlap between recorder paths and file-tool paths, and C6 passes those paths from the report reader to repository tracking.

- **C1, event parsing:** A session `tool/call` event carries `data.arguments` as a JSON string. The code stores the raw path, meaning the exact path string in the tool arguments before filesystem resolution, in an in-memory set under that event's turn only when the JSON parses to an object and the call matches the Host's rules. A `write` needs string `content` and a nonblank `file_path`; an `edit` needs string `old_string` and `new_string` and a nonblank `file_path`; `str_replace_editor` needs a `create`, `str_replace`, or `insert` command and a nonblank `path`. A missing or wrongly typed required field is an incomplete call. Invalid JSON, incomplete calls, `view`, and unrecognized tools store no path. The implementation matches this contract at [lib/changes.js:117-132](/home/wilder/dsh-test/dsh-completion-gate/lib/changes.js#L117-L132) and [lib/changes.js:182-190](/home/wilder/dsh-test/dsh-completion-gate/lib/changes.js#L182-L190).
- **C2, path conversion:** The turn's base is the working-directory field in its recorder summary, or the session working directory when the summary has no base. The `ChangeTracker.fileToolPaths` method resolves each raw path against that base, walks upward to the deepest existing ancestor, resolves symlinks for that ancestor, then appends any missing path components. It sorts and removes duplicates. This matches the Host's path helper for the tested relative-symlink and missing-leaf case ([lib/changes.js:137-150](/home/wilder/dsh-test/dsh-completion-gate/lib/changes.js#L137-L150), [lib/changes.js:194-203](/home/wilder/dsh-test/dsh-completion-gate/lib/changes.js#L194-L203), and [paths.ts:49-63](/home/wilder/git-repos/deepseek-harness-020/packages/deliverables/workspace-changes/src/paths.ts#L49-L63)). A working-directory string containing a symlink followed by `..` remains an unverified concern below.
- **C3, intersection and repository tracking:** The repository tracker adds a recorder path to the session's changed-file set only when the canonical absolute path also appears in `fileToolPaths`. The `(turn, seq)` idempotency key combines the turn number and the event sequence number; the code keeps that key unchanged. The tracker resolves each matching file's repository before adding any files. A failed repository lookup leaves the turn untracked, and the next status or report read retries it. The source contract is at [skeleton.md:60-70](/home/wilder/dsh-test/dsh-completion-gate/docs/work/k42t-adoption-and-direct-edits/skeleton.md#L60-L70); the symlinked-working-directory failure is documented under Correctness.
- **C6, report wiring:** `repositoryReport` reads the Host recorder's turn summary, passes the matching file-tool paths to repository tracking, and refreshes each tracked file's content digest. The digest records the file bytes used to detect whether evidence is still fresh. T2 does not change the Host recorder. The report reader marks child sessions as not recorded, and the Host recorder excludes subagent sessions ([lib/index.js:480-542](/home/wilder/dsh-test/dsh-completion-gate/lib/index.js#L480-L542), [lib/index.js:504-507](/home/wilder/dsh-test/dsh-completion-gate/lib/index.js#L504-L507), and [index.ts:58-61](/home/wilder/git-repos/deepseek-harness-020/packages/deliverables/workspace-changes/src/index.ts#L58-L61)).

The change meets the user stories in the spec for automatic path detection, excluding shell-only and different-path child or other-writer changes, accepting editor mutations, and avoiding model-declared change lists ([spec.md:43-47](/home/wilder/dsh-test/dsh-completion-gate/docs/work/k42t-adoption-and-direct-edits/spec.md#L43-L47)). The Spec reviewer found no separate finding; the C3 failure appears once under Correctness.

The skeleton assigns event and path code to M1 ([lib/changes.js](/home/wilder/dsh-test/dsh-completion-gate/lib/changes.js)), repository state to M2 ([lib/tracker.js](/home/wilder/dsh-test/dsh-completion-gate/lib/tracker.js)), and service wiring to M4 ([lib/index.js](/home/wilder/dsh-test/dsh-completion-gate/lib/index.js)). ## Correctness

### [P1] Canonicalize the recorder working directory before comparing paths: [lib/tracker.js:49-50](/home/wilder/dsh-test/dsh-completion-gate/lib/tracker.js#L49-L50)

**Status: The orchestrator accepted this finding after the orchestrator's symlink probe reproduced it; the Correctness reviewer also reproduced it independently.** The `fileTurn` method resolves each recorder path against the raw working-directory string in the turn summary, then compares that spelling with `fileToolPaths`, which returns canonical absolute paths ([lib/changes.js:197-202](/home/wilder/dsh-test/dsh-completion-gate/lib/changes.js#L197-L202)). A canonical path uses the filesystem's real spelling after following symlinks. The DSH Host resolves the working directory before resolving a file-tool path, stores recorder paths relative to that canonical directory, but retains the original working-directory string in its summary ([recorder.ts:136](/home/wilder/git-repos/deepseek-harness-020/packages/deliverables/workspace-changes/src/recorder.ts#L136), [recorder.ts:163-165](/home/wilder/git-repos/deepseek-harness-020/packages/deliverables/workspace-changes/src/recorder.ts#L163-L165), [paths.ts:96-98](/home/wilder/git-repos/deepseek-harness-020/packages/deliverables/workspace-changes/src/paths.ts#L96-L98), and [recorder.ts:357-365](/home/wilder/git-repos/deepseek-harness-020/packages/deliverables/workspace-changes/src/recorder.ts#L357-L365)). When the main session starts in a symlinked directory, the recorder path and the file-tool path therefore refer to the same file with different spellings. The tracker drops the overlap, contrary to C3.

The orchestrator ran `node cwd-symlink-probe.mjs` from a fresh copy using the original commit's [lib/changes.js](/home/wilder/dsh-test/dsh-completion-gate/lib/changes.js), [lib/tracker.js](/home/wilder/dsh-test/dsh-completion-gate/lib/tracker.js), and [lib/repositories.js](/home/wilder/dsh-test/dsh-completion-gate/lib/repositories.js). The probe supplied a turn summary with the Host's shape: a symlink in the working-directory field and the changed-file entry `app.js` relative to that directory. The probe did not run a real DSH Host session. Its output's `fixtureChanged: after` means the probe changed `app.js`; `recorderAbsolute` resolved it under `repo-link`, the symlink, while `fileToolPaths` resolved it under `repo-real`, the target directory. The tracker reported `tracked: []` because the same changed file had two different path spellings. The probe source is [cwd-symlink-probe.mjs](/home/wilder/Trash/t2-review/cwd-symlink-repro/cwd-symlink-probe.mjs).

The Correctness reviewer reproduced the same mismatch on a fresh archive of the original commit and returned `VERDICT: CHANGES-REQUIRED`. The Correctness reviewer also observed the changed fixture and the two different path spellings, and reported no other actionable defect.

Fix: The implementer should canonicalize the recorder's working-directory base before resolving recorder-relative paths, then compare and store canonical absolute paths. The implementer should add a service regression for a symlinked working directory in [tests/gate-changes.test.mjs](/home/wilder/dsh-test/dsh-completion-gate/tests/gate-changes.test.mjs), run `node --test --test-name-pattern='a session whose working directory is a symlink tracks the file it wrote' tests/gate-changes.test.mjs`, and then run `npm test`.

### Possible concerns

- **Symlink followed by `..`:** C2 is the contract for converting a raw file-tool path to its canonical absolute path. Neither the orchestrator nor the Correctness reviewer verified a working-directory string that contains a directory symlink followed by `..` against a real DSH Host session. To settle this concern, a Correctness reviewer should start a Host session with that working directory, issue a relative `write`, and compare the recorder's listed path with `ChangeTracker.fileToolPaths`. Result: unverified.
- **Event after disposal:** The DSH Host's `session/disposed` event marks a session as ended. Its `session/event` event carries session events such as `tool/call`. A `tool/call` event with an integer turn reaches `ChangeTracker.observe`, which creates an in-memory session entry before it checks the call arguments ([lib/changes.js:163-190](/home/wilder/dsh-test/dsh-completion-gate/lib/changes.js#L163-L190)). If the Host emits `session/disposed` and then `session/event` containing `tool/call` for the same session id, the event handler could recreate that entry. The DSH Host source does not establish whether that event order can occur. To settle this concern, a Correctness reviewer should run a Host lifecycle probe that emits exactly `session/disposed` followed by `session/event` with `type: 'tool/call'` and an integer turn for the same id, then inspect whether the change-tracker entry reappears. Result: unverified.
